Projet : un environnement sécurisé pour une application web

Objectif : déployer une application Node.js de façon à ce qu'un attaquant doive franchir plusieurs couches indépendantes. Je l'ai construit dans un laboratoire de test sur machine virtuelle et j'ai documenté chaque étape dans un rapport de 55 pages.

Ce qui arrive à une requête :

  1. Pare-feu (UFW)Seuls les ports nécessaires sont ouverts. Tout le reste est refusé.
  2. Chiffrement (HTTPS/TLS)Nginx déchiffre le trafic grâce à un certificat X.509 créé avec OpenSSL.
  3. Pare-feu applicatif (ModSecurity + règles OWASP)Le contenu de la requête est analysé pour détecter des attaques comme l'injection SQL.
  4. Reverse proxy et répartition de charge (Nginx)L'application n'est jamais exposée directement. Le trafic est réparti sur trois instances.
  5. Bloqué : tentative d'injection SQLUne requête de test a reçu une réponse 403 Forbidden sur les deux sites déployés.

Ce que j'ai fait

  • Installation, audit et durcissement d'Ubuntu Server 24.04 LTS
  • Configuration de Nginx : serveur web, reverse proxy et répartiteur de charge
  • Ajout de Fail2ban pour bannir les échecs répétés de connexion SSH
  • Déploiement d'une application web IA derrière le proxy, maintenue active avec PM2
  • Tests : HTTPS, pare-feu, bannissements, compression et pare-feu applicatif

Ce que j'améliorerais ensuite

  • Remplacer le certificat auto-signé par Let's Encrypt sur un vrai nom de domaine
  • Lancer l'application en mode production plutôt qu'en mode développement
  • Ajouter une surveillance des journaux avec alertes
  • Automatiser le déploiement avec un pipeline CI/CD sécurisé
